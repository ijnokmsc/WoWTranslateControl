3.1.0 （2026-09-23）
--------------------------------------------------------------
【新增】
* 发送消息过滤器（外发翻译精细控制）：
  - 免翻译前缀规则列表：控制台「Direct DLL 翻译选项」卡片
    可编辑（每行一条），消息以任一规则开头即原样发送不翻译；
    随 WoWTranslateDirect.json（outFilter 键）同步，游戏内
    /reload 生效
  - 外发频道开关：说/喊/密语/队伍/公会/官员/团队/团队警告/
    战场/世界 十个频道独立勾选是否参与翻译（outOff 键同步），
    关闭的频道发言原样放行
  - 内置恒生效：首字符为 . 或 。 的消息不翻译——私服命令
    （.additem 及带中文参数的命令）不再被翻译损坏；此前只要
    命令带中文就会被送翻导致命令失效
* 智能卸载：「游戏目录与部署」卡片新增「卸载 Direct DLL」按钮：
  - 删除 dinput8.dll / WoWTranslateDirect.dll / dlls.txt /
    WoWTranslateDirect.json（Wow.exe 运行中拒绝执行）
  - 自动判归属还原备份：wtc_backup/direct 中与 WTC 资产 MD5
    不同且不含 WTC 标识的文件（部署前用户原有的文件，如其他
    模组的 dinput8.dll / dlls.txt）自动还原；WTC 自有产物
    （含旧版本，标识串判定）不还原。备份目录保留
  - 卸载后控制台不再自动重装（SkipAutoDeploy 标记）；
    点「重新部署 Direct DLL」随时恢复
* llama-server 内存监控自动重启：
  - 「服务控制」卡片新增内存阈值（默认 4096 MB，可改）与
    自动重启总开关：工作集连续 60 秒超阈值自动重启回收
    （重启后 10 分钟冷却，防反复拉起），事件日志记录原因
  - 崩溃自动拉起：进程意外退出后 5 秒自动重启；距上次自动
    重启不足 5 分钟视为连续崩溃，暂停自动拉起待人工排查
  - 新增「重启 llama-server」手动按钮
* 版本号 3.0.0 → 3.1.0（驱动标识 v40 → v45）

【修复】
* 登录/进游戏偶发翻译失效与 Lua 报错（driver v41 → v45 逐层修复，
  已在 Frostmourne 服务器实测恢复）：
  - 报错形态："attempt to call global 'WoWTranslate_Diag'
    (a nil value)" 每条聊天弹一次，且被报错的消息被静默吞掉——
    登录期 Lua 状态会连续切换多次，注册 C 函数的状态与脚本实际
    执行的状态（FrameScript_Execute 内部走全局状态指针）可能错位，
    驱动过滤器在没有 API 的状态里空转
  - 静默形态：Lua 状态"同地址复用"使指针比较的状态切换检测失效，
    驱动不重注册、不重注入，表现为无横幅、无翻译、也无任何报错
  - 修复：引擎只把脚本注入当前全局状态（旧状态迟到的调用不再触发
    注入）；注册时记录全局表指针 + API 存活探针（复用注册自检的
    TValue 直读），识别到状态被替换即强制重新注册；驱动脚本激活前
    校验 API 存在，缺失则不注册过滤器、留给引擎重试
* 新增钩子存活心跳：引擎每 30 秒自查 lua_gettop 钩子字节并输出状态
  机快照（calls/globalL/注册与注入进度），钩子字节被外部还原时以
  ERROR 级别记录——用于定位部分服务器环境（如 Frostmourne 的
  rebuffed.dll 反作弊）静默拔钩导致的失联
* 驱动加载晚于进世界事件时聊天框不显示版本横幅：横幅改为进世界
  事件 +1 秒显示、加载 12 秒后仍未显示则强制补打
* 手动停止 llama-server 时事件日志先误报一次"异常退出"再变
  "已停止"：Kill 后 Exited 事件异步迟到被当作意外退出；
  现在主动停止/重启/退出期间抑制该误报，Start/Stop/Restart
  加生命周期锁防并发

3.0.0 （2026-09-14）
--------------------------------------------------------------
【重大变更 / Breaking】
* 彻底移除 GS 插件（Track A）支持，只保留 Direct DLL 自治引擎：
  - 删除"一键配置插件"、"切回 GS 备用轨道"与 GS 备用配置卡片
  - 不再写插件 INI/SavedVariables，不再打插件 Lua 补丁
  - 老 GS 插件用户：Direct DLL 部署后 WoWTranslate335.dll
    不再被加载（两条轨道共用 dinput8.dll 入口），插件自动失活；
    不删除游戏目录任何用户文件
  - 过滤规则只保留频道过滤（C0-C8），删除 R1-R6 内容规则开关
    （R7 乱码 / R8 中文在场质检为内部防线，继续生效）
* 删除统计区"按规则命中分布"卡片：Track B 架构下频道行恒为 0、
  外发流量不计入，数据失真无参考价值（顶部总/过滤/缓存/模型/
  错误计数保留）

【新增】
* 双层缓存：
  - 热层：命中 ≥3 次的词条晋升，持久保留不淘汰，重启不丢；
    消息先查热层——世界频道高频短句不再被刷屏挤出
  - 温层：按累计文本长度预算淘汰（替代固定条数上限），
    命中计数达到阈值自动晋升热层
  - 缓存条目持久化命中次数与真实最后使用时间（修复重启后
    淘汰顺序失真）；格式升级，2.x 旧缓存自动废弃
* 多客户端画像体系（架构）：引擎按客户端 exe 指纹（文件大小 +
  前 64K 的 MD5）自动匹配运行画像（grimfall-335a / wotlk-335a），
  两画像共享同一份地址表，新增客户端只需追加画像条目；启动
  日志输出指纹（size= md5[64K]= exe=）便于排查与适配
* llama-server 运行监控：
  - 状态栏每秒采样显示 llama-server 工作集内存（"PID x · N MB"）
  - 控制台启动时自动清理上次会话残留的 llama-server 孤儿进程
  - 每分钟追加一行 llama_mem.csv（time,pid,working_set_mb），
    供长跑内存增长分析；3.1.0 的超阈值自动重启即基于此
* 版本号 2.1.3 → 3.0.0（驱动标识 v35 → v40）

【已知限制】
* GrimfallWoW 客户端不兼容（2026-09-16 确认，放弃适配）：
  该客户端对 Lua 环境做了多层加固——Lua 调用的 C 函数必须位于
  Wow.exe .text 内（外部 DLL 函数指针直接 fatal）、宏命令
  （如 /cast [@cursor]）被限制、驱动注入所在的全局 Lua 状态
  始终不含 FrameXML 全局（ncw/ChatFrame1 恒 nil，进世界后亦然）。
  已实现函数指针白名单适配（.text 代码洞跳板）仍无法越过
  沙盒状态隔离。TriumvirateWoW 不受影响

【修复】
* 兼容带函数指针白名单的加固版客户端（分布式用户实测
  ERROR #134 "Invalid function pointer" 崩溃）：
  注册进 Lua 的 C 函数改为经 Wow.exe .text 节代码洞跳板
  （7 字节 mov/jmp，闭包持有白名单内地址、实际执行跳回 DLL），
  跳板对无守卫客户端无害，且已默认全量启用（含通用画像），
  防野外加固版构建崩溃
* Grimfall 适配过程中修掉的三处驱动缺陷：门禁探针 getfield
  读路径恒空，改为直读 TValue + rawget；PE 节头字段偏移误读，
  跳板此前只扫描 .text 前 1KB，修正 SizeOfRawData 偏移；生成
  脚本把签名字节双重转义致画像永不匹配，地址表去重为共享
  常量表。Grimfall 本身仍因 Lua 状态沙盒隔离不兼容，见【已知限制】
* /reload 后翻译永久失效（驱动假死，重启游戏才恢复）：注入门禁
  要求 Lua 栈深 ≤2，而世界态实测常为 3，/reload 后永远等不到
  注入窗口、日志无任何尝试记录；已放宽到 ≤3，并新增等待浅栈的
  跳过计数心跳日志（约每 200 次输出一次）便于诊断
* 控制台"DLL 日志"开关不生效：勾选后写游戏 json 时漏传 log
  参数被立即覆盖回 false，已修复（同步成功日志现在带 log 状态）
* 双软件对聊时 [TR] 译文行被对方客户端二次翻译：
  防回环守卫此前只认 [译]，现同时识别外发 [TR] 标识，
  含该标识的消息直接放行原文
* 沿用 2.1.3 全部修复（小队/团队漏替、断线熔断、兜底回显头部、
  译文标识位置统一）

2.1.3 （2026-09-14）
--------------------------------------------------------------
【修复】
* 小队频道英文消息不被替换（原文照显 + 译文追加成两行）：
  v33 让事件帧真正参与捕获后，当引擎把消息先派发给事件帧、
  压制过滤器后到时，过滤器拿到"重复"结果却没有任何处理分支、
  直接放行原文。现在压制过滤器对"首次/重复"统一处理：
  匹配同发送者最新待译条目并压制原文（团队频道同一机制，
  存在相同 bug，一并修复）
* 控制台未启动时聊天消息丢失频道和发送者 ID（只剩正文）：
  翻译失败兜底回显原先只显示正文，现重建完整头部
  （[频道] [玩家]： 原文，红色）；并新增断线熔断——网络类错误后
  15 秒冷却期内完全不捕获不压制，聊天 100% 原生显示零延迟，
  冷却结束后自动探测恢复（实测控制台关闭时每条消息阻塞约
  4.5 秒的根因是底层网络过滤驱动，换协议无效，熔断是正解）
* 修复上一版编辑遗留的 Lua 语法错误（压制过滤器函数缺少收尾，
  会导致注入的驱动脚本整体编译失败）
* 译文行频道标签统一：小队显示 [小队]（原为 [队伍]）

【变更】
* 译文标识位置统一：译文行改为 [频道] [玩家]： [译] 译文，
  标识紧贴正文前方（外发英文的 [TR] 前缀位置本就如此；
  字形保持中英区分——英文玩家客户端无中文字体，发 [译] 会乱码）
* 版本号 2.1.2 → 2.1.3（驱动标识 v31 → v35）

2.1.2 （2026-09-13）
--------------------------------------------------------------
【修复】
* EUI 聊天插件下世界频道消息完全不被翻译：
  改用引擎级事件帧捕获消息（任何聊天 UI 都无法拦截），
  消息正文与发送者直接取自事件参数，不再解析头格式
* 世界频道消息爆发时部分消息显示为带 [WTC] 前缀的英文：
  翻译排队超时阈值 30 秒 → 60 秒，超时回显不再带诊断前缀
* 服务器中转的其他玩家消息为 GBK 编码、本地输入为 UTF-8：
  引擎出站自动识别并归一为 UTF-8，中文 ID 玩家的英文消息
  不再被误判跳过

【新增】
* 外发译文等待时间可配置：游戏目录 WoWTranslateDirect.json 的
  outTimeout（秒，默认 25），适配本地推理冷启动

【变更】
* 译文统一显示在综合（General）聊天框
* EUI 下"译文替换原文"模式暂不支持压制原文（表现为追加显示），
  巨龙UI/原生界面不受影响

2.1.1 （2026-09-13）
--------------------------------------------------------------
【修复】
* 翻译消息丢失发送者：部分译文只剩正文、看不到谁发的
  （频道名 / 玩家名链接现在完整保留在译文头部）
* 世界频道英文消息不翻译：服务器中转的玩家消息为 GBK 编码，
  之前的中文检测误判后整条跳过；现 DLL 出站自动归一为 UTF-8，
  语言判定交由控制台规则，中文 ID 玩家的英文消息同样正常翻译
* 私聊（及其它外发）消息 10 秒后发出原文：外发译文路由缺失，
  现已恢复；外发等待时间可配置（WoWTranslateDirect.json 的
  outTimeout，默认 25 秒）

【变更】
* DLL 文件日志默认关闭：如需排错，在游戏目录 WoWTranslateDirect.json
  中将 "log" 改为 true 后，游戏内 /reload 生效（控制台也有开关）
* 控制台启动时自动比对游戏目录 DLL 与本地资源的版本
  （MD5），不一致自动重新部署——更新控制台后忘记重新部署
  也能自愈
* 部署备份策略简化：首次部署前自动备份现有 DLL（保留原始版本），
  之后直接覆盖——无需人工判断版本归属

2.1.0 （2026-09-13）
--------------------------------------------------------------
【新增】
* DLL 全自治：游戏内不再需要安装任何插件——DLL 自己捕获聊天、
  送控制台翻译、写回聊天框（原 GS 插件链路转为备用轨道）
* 外发翻译（中文→英文）：自己发的中文自动以英文发出，
  三种模式可选：关闭 / 只发英文（失败发原文） / 原文+英文都发
* 译文显示模式可选：译文替换原文 | 原文+译文（前缀追加），
  游戏内打 /reload 立即生效，无需重启客户端
* 端口冲突自动回退：8080 被占用时自动换下一个可用端口，
  并自动同步游戏目录配置（DLL 端点跟着变）
* 单实例保护：重复启动自动提示，防止端口占用冲突
* llama.cpp 便携化：默认使用程序目录下的 llama.cpp 文件夹
  （首次启动自动生成），推理线程数自动按 CPU 核心数适配
* 下载向导增强：
  - llama.cpp 下载完成后自动解压（含 CUDA 运行库包）
  - 识别手动放入的 llama-server.exe / 模型 gguf / 构建包
  - 「停止下载」按钮（取消并自动清理半截文件）
  - llama 目录大文件检测与「清理未使用大文件」按钮
    （区分使用中模型 / 未使用模型 / 遗留安装包 / 残留临时文件）
  - 手动下载指引（下载失败时给出地址与放置路径）
* 应用图标（任务栏 / 资源管理器 / 窗口）
* 首次使用引导：未安装 llama.cpp 时不再报错，自动跳过启动并指引用户

【修复】
* 中文系统频道不翻译：本地聊天、地下城向导、团队领袖、战场领袖
  等特殊频道头（全角冒号 / 中文频道名）完整支持
* 中文外发被误拦：外发请求不再受"已是中文"过滤规则影响
* 一系列乱码问题：
  - 译文开头出现 ?频道?
  - 译文出现 ⟦G12⟧ 之类占位符
  - [HC] 等标签被翻译成 [英雄的]（现原样保留）
* 偶发不翻译：引擎自动重试瞬时失败，并记录完整错误日志便于定位
* 首次使用（未安装 llama.cpp）时启动不再报错
* 下载中关闭窗口导致的文件占用与崩溃

【变更】
* 全链路 UTF-8：中文不再变成 ?（原 GS 插件的核心痛点）
* proxy_traffic.log 默认关闭（界面可开关，排错用）
* 缓存键升级：旧翻译缓存自动失效，不会被历史脏数据污染
* 过滤代理提示词与翻译方向随请求自动切换

2.0.0 及更早为内部开发版本，未对外发布。
